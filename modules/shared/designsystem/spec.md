# shared/designsystem

## Overview

Provide values generated from the front matter of the root `DESIGN.md` and common UI components built on them.

Located in `modules/shared/designsystem`. Only `core/utils` and `core/extensions` dependencies are allowed, and only when used. Do not depend on other shared modules, features, networking, or storage. Other `shared/*` modules must not depend on designsystem either.

## Public API

| Name | Behavior |
| --- | --- |
| `Tokens` | Color (light and dark), corner-radius, and spacing constants generated by `tools/generate.ts`; do not edit by hand |
| `DesignTheme` | App-wide theme. Applies the accent and other colors chosen from Tokens |
| `DesignCard` (iOS: `designCard()`) | Card with a surface background and thin line border, using Tokens' card radius |
| `languageTint` | Dot color for a programming language (Swift, Kotlin, TypeScript, Rust; muted otherwise) |

## Common UI

Provide LoadingIndicator, EmptyState, ErrorState, and StatusBadge. Errors include accessible text and a retry action. Badges communicate state through text as well as color. Text sizes follow OS settings.

RepositoryRow receives RepositoryRowData (string and numeric display values only) and image-loading behavior, sharing row rendering across search, details, and saved lists. It does not depend on API models or persistence. Use a fallback when image loading fails. A row shows the repository name in a monospaced face, an optional description in muted color, then the language (with its tint dot), star count, and a saved label in the primary color. These items wrap onto the next line when the width runs out, and never truncate or hide the star count. It draws no background; callers wrap rows in a card (`DesignCard` / `designCard()`).

## Design tokens

Colors are background, surface, onBackground, muted, line, and primary, each with light and dark values in `DESIGN.md` (`colors` and `colorsDark`; every color needs both). Corner radii (`rounded`) are avatar, chip, card, hero, and pill; spacing is small, medium, and large. Screens use Tokens instead of hard-coded colors or radii. Tappable elements are at least 44pt/dp.

## Theme

Apply `DesignTheme` once at the top of the app. Screens and system bars follow OS light/dark settings, preserving contrast between backgrounds, text, and icons. Reflect OS theme changes while the app is running.

## Platform differences

The iOS module is `DesignSystem`, with implementation in `Sources/Shared/DesignSystem` and tests in `Tests/Shared/DesignSystem`. The Android package is `com.example.shared.designsystem`.

On iOS 26 and later, gate Liquid Glass components with `#available` and keep them inside this module.

- iOS lists use `designScreenBackground()` (Tokens' background) and `designListRow()` (no separators, no row background) so each card stands alone; Android screens get the background from `DesignTheme`.
- iOS `designTheme()` aligns the accent color (tint) with Tokens; background/text colors and automatic system-bar appearance changes use standard SwiftUI.
- Android `DesignTheme` builds Material 3 light/dark color schemes from Tokens, consistent with `enableEdgeToEdge()` system-bar appearance. The launch-window theme also switches through `values` / `values-night`.
- Before a row image loads, iOS displays a person icon and Android displays the owner's initial. Stars use an icon on iOS and a text label on Android.

## Localization

Callers provide LoadingIndicator's label, ErrorState's retry label, and RepositoryRow's star-count/saved labels. Do not embed UI text or depend on core/localization internally.
